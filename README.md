# Score to MIDI — スコア読み取り機

PDFの譜面をブラウザー内で認識し、原稿と照合・修正してMIDI / MusicXMLを保存する開発初期版です。GitHub Pagesで配信できる静的アプリです。譜面は外部サーバーへアップロードしません。ライブラリ・モデル取得時はCDNに接続します。

## 目標

1. PDF・画像を読み込み、指定したページの音符を認識する。
2. 原稿と認識した楽譜を並べ、再生・修正できるようにする。
3. 小節の拍数を検査し、確認候補を表示する。
4. MIDIとMusicXMLを保存する。
5. ジングルベルのスキャンスコアで精度・性能を検証する。

## 使い方

私用を前提とし、通常画面には開発用サンプルを表示しません。Windowsでは初回準備後、`Start-ScoreToMidi.cmd`をダブルクリックするとローカルサーバーと画面を起動できます。終了時はサーバーのウィンドウでCtrl+Cを押します。HTMLファイルを直接開く方法には対応していません。

現在のChrome / Edgeなど、WebAssembly対応のPCブラウザーを推奨します。

1. 開始・終了ページを指定し、PDFを選択します。最初は1ページに絞ってください。
   吹奏楽など、ページ全体が同時に鳴る1段の大編成スコアでは「大編成スコア」を選びます。1ページに複数段ある譜面にはこのモードを使わないでください。
2. 初回は認識モデル約150 MBに加え、Python・画像処理ライブラリを取得します。通信と端末性能により時間がかかります。
3. 原稿と認識結果を照合します。音符をクリックし、下部のボタンで音高・音価・臨時記号などを修正できます。
4. 再生して確認し、「MIDI保存」を押します。編集を続ける場合はMusicXMLも保存してください。

「パート名・音色・移調を確認」でパートごとの設定を変更できます。楽器名はOCRの位置情報から候補を取り出します。複数楽器の併記は自動で1つに決めません。楽器を選ぶとパート名とMIDI音色を変更し、移調は「選択楽器の移調を適用」で明示的に設定します。実音譜では移調を0にしてください。画面内再生は確認用の簡易音源で、MIDIで指定した各楽器の音色を再現する音源ではありません。

16トラック以上の大編成では、音色のチャンネル衝突を防ぐためMIDI Portメタイベントで複数ポートに分けます。ポート情報を無視する再生ソフトでは音色が干渉する可能性があるため、その場合はMusicXMLを楽譜ソフトへ読み込んでください。打楽器の自動マッピングは行わず、メロディ用の出力ではチャンネル10を避けます。

設定と最新の編集結果をこのブラウザーに自動保存します。「前回の編集を再開」または保存したMusicXMLの読み込みで編集を続けられます。原稿画像・取り消し履歴は自動保存に含みません。ブラウザーデータの削除で失われるため、MusicXMLでも保存してください。Pagesとローカル版は別の保存領域です。

保存ファイル名は曲名欄の名前を使い、MIDIは`.mid`、MusicXMLは`.musicxml`を付けます。日本語・英語OCRで中央の大きな見出しを曲名候補として探し、右寄せの作曲者名やテンポ表記を除外します。曲名が取れない場合は元ファイル名を使用し、「スコア」「scan001」などの汎用名しかない場合は`曲名不明_年月日_時分秒`を使います。曲名欄で修正でき、設定パネルで実際の保存名を確認できます。OSで使えない記号・予約名・長すぎる名前は安全な名前に置き換えます。

処理を中止するとページを再読み込みします。認識中の途中結果は保存しません。

## 技術構成

- PDF.js: PDFを200 dpiの画像に変換
- homr + ONNX Runtime Web: 五線検出とニューラルネットワークによる譜面認識
- Pyodide + OpenCV: 既存のPython画像処理・認識ロジックをブラウザーで実行
- Web Workers: 重い処理を画面操作から分離
- Verovio: MusicXMLからの譜面描画・MIDI生成
- Web Audio: 簡易音源で確認再生
- 独自追加: 日本語操作画面、PDFページ範囲指定、拍数の不一致検査、モデルのSHA-256検証

## タイ・MuseScore・処理機器

認識済みのタイは音をつなぐ`tie`と表記用の`tied`を揃えて保持します。同音の隣接音符に付いたスラーはタイへ補正します。画像上の曲線も照合しますが、符幹・連桁との誤検出があるため候補として表示します。原稿をプレビューして「確認してタイにする」で適用してください。音符を選んで「次の同音にタイ」またはTキーでも修正できます。異なる音高のスラーはタイに変換しません。

MuseScore Studio 4には「MuseScore用MusicXML」の読み込みを推奨します。楽器名・楽器種別・GM音色・移調を保存します。MIDIは音高・長さ・GM音色を渡せますが、タイやスラーなどの記譜は保持できません。認識結果で末尾の小節が欠けたパートは、MusicXMLの書き出し時に「認識欠落：原稿を確認してください」と記した空の小節を追加します。音符や音価は推測しません。MuseScoreが空欄を休符として表示しても、原稿の休符を認識したという意味ではありません。

「認識に使う機器」は自動・GPU優先・NPU優先・CPUのみから選べます。自動ではブラウザーが公開するWebNNのNPU、WebGPU、CPUの順にモデルごとに試し、非対応演算・初期化失敗・実行失敗ではCPUへ切り替えます。一部演算がCPUで実行される場合もあります。使用経路は処理状況と検証欄に表示します。GPU/NPUが搭載されていても、ブラウザー・ドライバー・モデルの対応が必要です。NPU用WebNN APIを公開しないブラウザーではGPUまたはCPUを使います。PDF画像化・OCR・幾何解析の全処理をGPU/NPUへ移したものではありません。

## その他の記号

「記号の検証・修正」に、出力されている記号の数と、スラー・ヘアピンの終端不整合を表示します。記号の数は認識精度を示すものではありません。

- 原稿の点形状を音符座標・五線と照合し、スタッカートの未出力候補を表示します。点が見つからない既出記号は「未検証」の一覧に分けます。明瞭な点・アクセント・くさび形は補完し、曖昧な結果は確認用に残します。既存記号は自動削除しません。候補ボタンで原稿の位置を確認して修正できます。
- OCRの強弱（mf、sfzなど）と奏法・速度文字（cresc.、pizz.、arcoなど）を五線外の位置・文字サイズ・信頼度で絞り、音符の位置に補います。同じ位置の既存強弱と重複する場合は追加しません。文字を歌詞として重ねて追加することも防ぎます。
- 音符を選択し、スタッカート、アクセント、テヌート、マルカート、フェルマータ、ブレス、トリル、モルデント、ターン、アルペジオを追加・解除できます。強弱・奏法文字は選択位置の一覧から削除できます。
- 始点と終点の音符を選び、スラー・クレッシェンド・デクレッシェンドを追加できます。範囲記号を削除すると対応する両端を削除します。取り消し・やり直し・自動保存に対応します。
- 音部記号・調号・拍子は選択小節の対象五線から修正できます。音高は移調しません。原稿の誤読で音高も違う場合は音符側の修正が必要です。

画像による独立照合は現在、五線・小節線・タイ候補・スタッカート・アクセント・スタッカティッシモの形状に対応しています。装飾、調号、反復など全記号の画像検出を新たに実装したわけではありません。これらは既存OMRの認識と手動修正を使います。原稿との完全一致や全ページの認識精度は未達です。MIDIには記譜そのものを保存できないため、MuseScoreへの受け渡しはMusicXMLを使ってください。

## 五線・小節線・記号の構造解析

認識前にWeb Workerで画像を二値化し、±2度の傾きを推定します。長い横線を等間隔の5本にまとめて五線を検出し、左右端・四隅・各線の座標列を取得します。線間隔を基準に縦線を検査し、符頭や連桁とつながる縦棒を除外して小節線候補を作ります。複縦線は1つの境界にまとめます。

大編成スコアでは、複数パートで同じ横位置にある小節線を照合します。他パートから補う境界は「推定」として区別し、原稿上では破線で表示します。独立に検出した五線を楽器名のOCR対応にも使用します。

認識後はhomrが出力した音符・休符の種類、音高、音価、座標を五線・小節に割り当てます。小節数の不足、小節位置の不一致、対応する音符・休符がない五線を確認候補として表示します。新しい記号分類モデルを別に学習したものではなく、画像の構造解析と既存OMRを組み合わせる方式です。音符の欠落を推測で自動追加することはありません。

「五線・小節線を表示」で原稿への重ね合わせを切り替え、「五線・小節・記号の検証結果」で確認候補を表示します。解析JSONには以下を保存します。

- 原稿左上を原点とするピクセル座標、五線の5本の線、左右端、小節線候補、推定境界
- 音符・休符の種類、音高、音価、声部、和音、五線内の半間隔単位の位置
- ページ内の五線番号・小節番号、MusicXMLの小節番号、照合の警告
- `page`は選択範囲内の0始まり、`sourcePage`は元PDFの1始まりのページ番号。`onset`と`duration`はMusicXMLのdivisions単位で、四分音符の長さが`divisions`

解析情報はMusicXMLとブラウザー内の編集保存にも保持します。原稿画像がない再開時は解析の一覧・JSON保存に対応し、画像への重ね合わせは行いません。

検出は補助的な幾何判定であり、`confidence`は統計的な正解確率ではありません。大きな湾曲、強い傾き、細い線の欠損、1線の打楽器譜、特殊な小節線には未対応または誤検出の可能性があります。自動モードの段分けも暫定判定です。

既存の[Sheetscan](https://github.com/dsalex1/sheetscan)を基盤にしています。出典・ライセンスは[THIRD_PARTY.md](THIRD_PARTY.md)を参照してください。

## 制約

- 自動認識は誤りを含みます。拍数検査は精度保証ではなく、弱起などの正常な例外も候補に含みます。
- 楽器名OCRは誤りや欠落を含みます。名前が取れなかったパートは「楽器未確認」と表示します。楽器選択と移調を確認してからMIDIを保存してください。
- 打楽器、タブ譜、複雑な声部、反復、アーティキュレーションは正確に再現されない場合があります。
- 大編成・多数ページはメモリと時間を消費します。PCで1ページずつ検証してください。
- モデル・依存ライブラリの配信元への通信が必要です。完全オフライン動作は保証しません。
- homrの学習データに非商用制限がある旨が上流で説明されています。商用利用を想定する場合は事前に確認してください。

## 音符の欠落・座標と楽器割り当て

- 推定座標を、独立した符頭検出の位置に一対一で対応付けます。対応が曖昧な位置は無理に移動しません。位置補正だけでは音高・音価は変更しません。原稿上の丸印は認識位置を示し、正解を保証する表示ではありません。
- 大編成モードでは、独立した五線検出にあるのに認識側で欠けた五線を切り出し、再認識を試します。単一パートの音符が得られた場合に元の順序へ挿入します。推測で音符を作る処理ではありません。複数段の譜面では自動実行しません。
- 左側の楽器名は五線ごとに拡大して別にOCRします。認識位置は先頭の1音だけで決めず、パート内の複数の座標で対応付けます。切り出しで併記候補が欠けた場合は、より多く候補を読めた全体OCRを優先します。
- 代替楽器が併記されたパートは、原稿の先頭候補を仮割当し、候補の文字列はパート設定とMusicXMLのメタデータに残します。楽譜上には割り当てた楽器名を表示します。一律ピアノへ戻す処理を廃止しました。編成上どの楽器を使うかは候補から変更してください。
- 実音楽器の調号が一致している場合、それを基準に移調を照合します。例: 実音F調・クラリネットG調なら−2、アルトサックスD調なら−9。実音譜の同じ調号では0を維持します。調号が整合しないときは自動で決めません。
- 打楽器の専用音色・奏法への自動割当て、個々の音符のすべての欠落、誤った音高・音価は未解決です。保存した古い編集結果には新しい認識処理が適用されないため、PDFを読み込み直して再認識してください。

Python補助処理の単体検証は`python -m unittest discover -s tests -p '*_test.py'`で実行できます（モデル・OpenCV不要）。

## スタッカート・アクセントとページ結合（処理版2026-11-22-articulation-merge-3）

画像の点・アクセント・くさび形を別々に照合し、明瞭な形状はMusicXMLへ補完します。点とアクセントが同じ音符に付く場合も両方を保持します。小さく切れたスラーの端は点に似るため、周囲の線も調べます。補完を含め、全記号の正誤を保証する処理ではありません。

MIDIと画面内再生には奏法を反映します。スタッカートは発音を記譜音価の50%、スタッカティッシモは25%にし、アクセントはMIDI velocityを18、強いアクセントは28加算します（上限127）。これは本ツールの演奏方針です。発音開始・次の音の時刻は変えず、タイの連続音を短く切りません。同音が他の楽器で鳴る場合は別トラックとして扱います。[Verovioの基本MIDI出力](https://book.verovio.org/toolkit-reference/output-formats.html)をそのまま使用せず、奏法を後処理しています。

MIDIは点やアクセントの形を格納しません。MuseScoreで記号の形を残したい場合は「MuseScore用MusicXML」を開いてください。MIDIからの再採譜では短い音符と休符などへ変わる場合があります。

大編成モードでは、ページごとのコンパクトなパート番号で結合せず、五線位置の単調対応で同じパートを結びます。途中の五線が欠けても以降の楽器をずらしません。対応が取れない箇所は警告と認識欠落の空欄にし、時刻を保持する非表示の休符を明示します。これは認識済みの休符ではありません。先頭小節の音符座標が次の物理小節へはみ出している場合は、その五線を再認識し、位置整合が改善した場合だけ置き換えます。

解析JSONには`recognitionVersion`を保存します。旧結果の読み込み時にはPDFの再認識が必要なことを表示します。
